# 模範GD台本ガイド

デモ台本（`src/scripts/*.ts`）を書くときの基準。就活サイトで一般的に紹介されている GD の進め方・役割・コツを、20分・5人のデモ用に整理したもの。

参考: ワンキャリア「グループディスカッションの進め方」/ キャリタス就活「GDの流れと役割」/ マイナビ「GDの進め方と練習方法」

## 1. 流れと時間配分（20分）

| p | フェーズ | 分 | やること |
|---|---|---|---|
| 0 | 役割決め・時間配分 | 2 | あいさつ → 役割を決める（立候補・推薦）→ TK が時間配分を提案し全員で合意（予備時間も確保） |
| 1 | 前提確認・定義 | 3 | ゴール（何を出せば結論か）、言葉の定義、5W（誰の・いつ・どこの）、答えの形を決める |
| 2 | 現状分析・課題特定 | 3 | 現状と理想のギャップ、要素分解（例: 売上＝客数×客単価×頻度）、原因の切り分け |
| 3 | アイデア出し（発散） | 4 | 質より量、否定しない、理由つきで出す、全員が発言 |
| 4 | 検証・絞り込み（収束） | 4 | 評価軸（効果・実現性・コストなど）を先に合意 → 軸で比較 → 懸念を建設的に扱う |
| 5 | 結論・発表準備 | 2 | 結論を1つに決めて全員で合意、発表者が構成を確認 |
| 6 | 発表 | 2 | 発表者だけが「結論 → 根拠 → 具体策」で約1分 |

TK が伝える残り時間の目安: p1 開始で残り18分 / p2 で15分 / p3 で12分 / p4 で8分 / p5 で4分 / p6 直前で2分。

## 2. 役割ごとの模範行動（台本に必ず入れる）

**司会（はると・s0）** — 仕切り役ではなく「全員が話しやすい場をつくり、議論を前に進める役」
- 最初に流れ（ゴール→前提→分析→発散→収束→結論）を示す
- 発散と収束の切り替えを宣言する（「今は発散なので否定なしでいきましょう」「ここから収束に入ります」）
- 発言の少ない人に答えやすい質問を振る（「そうたさんは賛成ですか？気になる点ありますか？」）
- 要約して認識をそろえる（「〇〇という認識で合っていますか？」）
- 脱線したら受け止めてからゴールに戻す
- 自分の意見を押しつけない（意見を言う時は役割外として控えめに）

**タイムキーパー（さくら・s1）**
- 配分を提案し、予備時間（1分程度）を確保する
- フェーズの区切りで残り時間と次にやることを伝える
- 押しているときは具体的に調整案を出す（「2分押しているので、検証を1分短くしましょう」）
- 時間管理だけでなく自分の意見も出す

**書記（ゆうき・s2）**
- 全部を書き取らず、キーワードと共通点でグルーピングして共有する
- 出た意見を「〇〇系と△△系に分けられます」と構造化して見せる
- 論点の抜け漏れや前提とのズレを指摘する（「まだ〇〇の視点が出ていません」）
- 結論前に、ボードを発表の順番（前提→課題→施策→理由）に並べ直す
- 自分の意見も出す

**発表者（みお・s3）**
- 早い段階から結論の形を意識していることを示す
- 発表前に、結論と根拠を自分の言葉で要約して全員に確認する（「付け足しはありますか？」）
- 発表は結論から。根拠と具体策（5W1H）を簡潔に、グループの代表として話す

**メンバー（そうた・s4）** — 役割はないが議論の主役の一人
- 新しい視点、行き詰まりの打開、具体例やデータで議論を厚くする
- 「なぜそう思いますか？」と理由を確認して深める
- 役割を奪わず、役割者をフォローする（例: 時間を気にする一言、書記への補足）

## 3. 全員に共通するコミュニケーション

- 結論から話し、理由を添える（「私は〇〇だと思います。理由は〜」）
- 賛成ははっきり言葉にし、乗っかって広げる（「いいですね、それなら〜も」）
- 反対はまず受け止めてから（「確かに〇〇ですね。ただ△△の点が気になっていて〜」）
- 数字・事実・身近な具体例を根拠にする
- 相手の名前を呼んで話を振る・受ける

## 4. デモに入れるリアルな場面（各台本で1〜2個）

- 誰かが少し脱線する → 司会が受け止めてからゴールに戻す
- 議論が押す → TK が具体的な調整案を出し全員が合意
- 意見が割れる → 評価軸に立ち返る、または両案の役割の違いで組み合わせる
- 発言の少ない人がいる → 司会が答えやすい形で振る

## 5. テーマの型ごとのポイント

- **ビジネス型**: ゴールを数値で置く → 要素分解 → どの要素を伸ばすかの仮説 → 施策 → 効果・実現性・コストで絞る
- **課題解決型**: あるべき姿を先に描く → 現状とのギャップ＝課題 → 原因の切り分け → 原因に効く施策
- **抽象テーマ型**: いきなり意見を出さず、言葉の定義・誰にとって・どんな場面かを決める → 意見の共通点 → 上位概念で1つの答えにまとめる
- **フェルミ推定型**: 答えの単位と対象範囲を定義 → 式（需要側か供給側か）を設計 → 要素を分解して数値を仮置き（根拠つき）→ 計算 → 別の方法や実感で妥当性チェック。計算は正確に
- **選択・ディベート型**: 誰の立場で判断するか・判断基準と優先順位を最初に合意 → 両案のメリット・デメリット → 基準で判定 → 条件つきの結論

## 6. 重要場面（key）の書き方

- 役割を持つ人が「その役割として大事な一言」を言った発言に付ける（8〜11個）
- title: その行動を一言で（20文字以内）
- why: 「なぜこのタイミングでこれを言うのが大事か」。やらないと何が起きるか、言うとどう変わるかを具体的に（60〜110文字）
